PARROT DERIVATIVES LAYOUT
=========================

What each folder of the output (derivatives) tree contains. Only the files that matter
downstream are listed explicitly; for the rest, refer to the documentation of the tool that
produced them.

THE ONE STRUCTURAL RULE
-----------------------
The output is a BIDS-derivatives tree, laid out STAGE-MAJOR:

    <output_dir>/<stage>/sub-<ID>/...

Every stage folder holds one sub-<ID>/ directory per subject -- no exceptions. Below, each
stage is shown once with its `sub-<ID>/` level; `sub-<ID>` stands for the participant label
(e.g. `sub-010002`). Wildcards: `*` in a filename stands for a varying field (atlas
resolution, spacing, hemisphere, ...).

Companion docs: CLAUDE.md (pipeline overview, conventions, gotchas) and the per-subject QC
report at qc/sub-<ID>/index.html (which validates most of what is described here).


ROOT
----
.
├── legend_of_files.txt: this file. Copied into the output dir by bin/run_reconstruction.sh on
│   every run, so a derivatives tree stays self-documenting once detached from the repo.
├── logs/: run logs. ALSO the pipeline's idempotency markers -- a step is skipped when its
│   │      <stage>_log.txt exists, so deleting that file (NOT the outputs) forces a rerun.
│   ├── artifact-setup_log.txt: one-time pre-loop EEG-artifact template fetch (HArtMuT + MNI).
│   ├── qc-group_log.txt: group QC pass, run after the subject loop.
│   └── sub-<ID>/
│       ├── parrot-reconstruction_log.txt: the subject's top-level run log (not a step marker).
│       ├── <stage>_log.txt: success marker + log of one step. Some stages split into several
│       │   independently-guarded sub-steps: dipoles-<spacing>mm, forwardsolvers-{openmeeg,
│       │   simnibs,cgal,anisotropic}, artifacts-{registration,dipoles,leadfields},
│       │   connectivity-{atlas,matrices}.
│       ├── <stage>_log.txt.partial: live output of a step still running (or killed). Never a
│       │   success marker -- a SIGKILLed step leaves only this, so it re-runs.
│       └── FAILED_<timestamp>_<stage>_log.txt: preserved log of a failed attempt (debugging
│           only; never a success marker).
└── (hidden caches, safe to delete; regenerated on demand)
    ├── .templateflow/: TemplateFlow cache (QSIPrep templates + the MNI152NLin2009cAsym T1w
    │   used by the artifact registration). Persistent across runs.
    ├── .hartmut_cache/: fetched HArtMuT assets (GPL-3.0, fetched-at-use, not vendored).
    ├── .hippunfold_cache/: HippUnfold model cache.
    └── .parrot_work.XXXXXX/: scratch for BIDS apps (QSIPrep/nipype); swept on exit.


ANATOMICAL RECONSTRUCTION
-------------------------
├── raw/: standardized working inputs written by the ingest stage (T1 MPRAGEised when the
│   │     subject is MP2RAGE, else copied; T2 copied). Every downstream stage reads THESE,
│   │     not the BIDS originals. DWI is the exception -- it stays on the BIDS dwi/ path.
│   └── sub-<ID>/
│       ├── T1.nii.gz (+ T1.json: provenance sidecar -- Sources, GeneratedBy, Operations)
│       └── T2.nii.gz (+ T2.json): only when the subject has a T2/FLAIR.
│
├── fastsurfer/: FastSurfer output. ALWAYS runs. Two roles, depending on --recon-backend:
│   │   - CNN subsegmentations (CerebNet/HypVINN) -- always from here;
│   │   - cortical surfaces -- from here in the default "full" mode.
│   │  It is a FreeSurfer SUBJECTS_DIR, so the mne / schaefer / freesurfersubcortical stages
│   │  write INTO it (bem/, Schaefer_LUT/, mri/, label/). With --recon-backend freesurfer (or
│   │  a staged HCP recon) the surfaces and those three stages land in freesurfer/ instead,
│   │  and this folder keeps only the CNN subsegs.
│   └── sub-<ID>/
│       ├── FreeSurferColorLUT.txt: FreeSurfer LUT (installed by the pipeline; the recon
│       │   tools do not ship it here).
│       ├── Schaefer_LUT/: LUTs for the Schaefer atlases (installed by the pipeline).
│       ├── bem/: MNE watershed BEM surfaces (`mne` stage). On MP2RAGE subjects watershed is
│       │   run on INV2, not the UNI -- the UNI has no scalp/air contrast.
│       ├── mri/
│       │   ├── cerebellum.CerebNet.nii.gz: cerebellar volumetric labels (CerebNet).
│       │   ├── hypothalamus.HypVINN.nii.gz: hypothalamic labels (HypVINN).
│       │   ├── aseg.mgz / aparc+aseg.mgz: standard segmentations.
│       │   ├── schaefer*_aparc+aseg.mgz: volumetric Schaefer atlas in subject space, one per
│       │   │   resolution 100..1000 (`schaefer` stage).
│       │   ├── ThalamicNuclei.mgz, brainstemSsLabels.mgz, {lh,rh}.hippoAmygLabels.mgz:
│       │   │   FreeSurfer subcortical streams (`freesurfersubcortical` stage).
│       │   └── INV2.mgz: conformed MP2RAGE INV2, only on MP2RAGE subjects (BEM input).
│       ├── surf/: lh/rh .white .pial .thickness .area .volume -- cortical surfaces and their
│       │   per-vertex metrics.
│       └── label/: cortical annotations, incl. the resampled Schaefer *.annot files.
│
├── freesurfer/: present ONLY when surfaces come from recon-all (--recon-backend freesurfer)
│   │            or from a staged HCP recon. Same internal layout as fastsurfer/ above
│   │            (bem/, Schaefer_LUT/, mri/, surf/, label/). Otherwise this folder is absent.
│   └── sub-<ID>/
│
├── hippunfold/: HippUnfold output -- hippocampal/dentate surfaces and subfield labels.
│   └── sub-<ID>/
│       ├── LABELS.txt: labels used in the atlases generated by the tool.
│       ├── anat/
│       │   └── sub-<ID>_hemi-{L,R}_space-T1w_desc-subfields_atlas-multihist7_dseg.nii.gz:
│       │       volumetric hippocampal subfield labels in subject space.
│       ├── surf/
│       │   ├── sub-<ID>_hemi-{L,R}_space-T1w_den-0p5mm_label-{hipp,dentate}_midthickness.surf.gii
│       │   ├── ..._surfarea.shape.gii: per-vertex area of the surface above.
│       │   ├── ..._thickness.shape.gii: per-vertex thickness of the surface above.
│       │   └── ..._label-hipp_atlas-multihist7_subfields.label.gii: per-vertex subfield labels.
│       ├── coords/, warps/: HippUnfold's internal unfolded-space coordinates and transforms.
│       └── qc/: HippUnfold's own QC images (not Parrot's QC).
│
├── simnibscharm/: SimNIBS 4.5 `charm` head segmentation.
│   └── sub-<ID>/
│       ├── final_tissues.nii.gz: tissue label field. SimNIBS writes it 4D as (X,Y,Z,1)
│       │   (degenerate trailing axis); the tissuelabels stage squeezes it to plain 3D.
│       ├── final_tissues_LUT.txt: LUT for the label field above.
│       ├── labels.txt / conductivities.txt: label names + SimNIBS conductivities, installed
│       │   by the pipeline. These are what the SimNIBS-mesh DUNEuro solve reads.
│       ├── subject.msh (+ .opt): SimNIBS tetrahedral head mesh -- meshed directly by charm
│       │   from the label field; the FEM mesh used by the `duneurosimnibs` leadfield.
│       ├── converted/: surfaces extracted from subject.msh (feed surfaces/charm_*.ply).
│       ├── surfaces/, segmentation/, label_prep/: charm intermediates.
│       ├── eeg_positions/: SimNIBS's own EEG montage + Fiducials.csv (MNI template fiducials
│       │   warped to the subject). NOT used as a fiducial source: those template LPA/RPA sit
│       │   ~7.6 mm posterior of the preauricular point -- see scalplandmarks/fiducials.json.
│       ├── toMNI/: subject<->MNI transforms computed by charm.
│       ├── T1.nii.gz, T2_reg.nii.gz: charm's conformed inputs.
│       └── charm_report.html / charm_log.html: SimNIBS's own report.
│
├── fslfirst/: FSL FIRST subcortical segmentation.
│   └── sub-<ID>/
│       ├── T1.nii.gz: bias-field-corrected T1 (ANTs N4) -- FIRST's actual input.
│       ├── FSL-<STRUCT>_first.vtk: one surface per structure, where <STRUCT> is one of
│       │   BrStem, {L,R}_{Accu,Amyg,Caud,Hipp,Pall,Puta,Thal}.
│       ├── FSL-<STRUCT>_first.bvars: FIRST's shape-model coefficients (diagnostics).
│       ├── FSL_all_fast_firstseg.nii.gz: all structures as one volumetric label field.
│       └── FSL_all_fast_origsegs.nii.gz: per-structure 4D segmentation before conflict resolution.
│
├── synthstrip/: SynthStrip brain extraction.
│   └── sub-<ID>/
│       ├── T1_stripped.nii.gz (+ _mask.nii.gz): skull-stripped T1 and its mask.
│       └── T1_noCSF_stripped.nii.gz (+ _mask.nii.gz): tighter variant excluding CSF, used as
│           the registration target for the cerebellum/bigbrain warps.
│
├── cerebellum/: ANTs registration of the subject to the cerebellar atlas (the atlas ships the
│   │            surfaces; they are warped INTO the subject, not extracted from it).
│   └── sub-<ID>/
│       ├── LABELS.csv: cerebellar atlas labels.
│       ├── T1_stripped_N4corrected.nii.gz: the moving/fixed image used for the registration.
│       ├── affine_*.{vtk,nii.gz}: atlas surfaces/volumes brought to subject space, affine only.
│       ├── nonlinear_*.{vtk,nii.gz}: same, after the nonlinear warp (these are the ones used).
│       │   The surface set is Cerebellum_Surf_{GM,WM}_Labels, Cerebellum_Inner_Surf_With_Features
│       │   and its manifold-repaired variant; the volumes are {gray,white}_labels and
│       │   template_brain.
│       ├── nonlinear_DTI.nii.gz: cerebellar diffusion tensor warped from the template (PPD
│       │   reorientation), MRtrix component order. Fills cerebellar WM for the anisotropic
│       │   conductivity model. Optional -- only when the cerebellum template ships a DTI.
│       └── transform_files/: the computed subject<->template transforms.
│
├── bigbrain/: ANTs registration of the subject to BigBrain, for cortical neuronal density.
│   └── sub-<ID>/
│       ├── subject_full16_100um_2009b_sym.nii.gz: BigBrain cell-staining intensity warped into
│       │   subject space. Consumed by place_dipoles.py to weight each dipole by neuronal
│       │   density (-> dipole_neural_density.npy -> the processed leadfields).
│       ├── T1_stripped_N4corrected.nii.gz: the image the registration was driven on.
│       └── transform_files/: the computed subject<->BigBrain transforms.
│           NOTE: a warp can "succeed" (ANTs reports OK) while covering only a fraction of the
│           brain, which silently zeroes the density of the uncovered sources. The QC stage
│           checks warp coverage -- read it before trusting a leadfield.
│
├── surfaces/: every surface from every tool, converted to WORLD (T1 scanner RAS) space and
│   │          aggregated here with a uniform naming scheme. This is the surface API of the
│   │          pipeline -- downstream stages read from here, never from the tool folders.
│   └── sub-<ID>/
│       ├── charm_<tissue>.ply: SimNIBS charm tissue boundaries -- blood, bone_compact,
│       │   bone_spongy, CSF, eyes_balls, eyes_muscles, gray, scalp, white.
│       │   (charm_scalp.ply is the scalp used for electrodes/landmarks; charm_eyes_balls.ply
│       │    is where the artifact stage samples the eye dipoles.)
│       ├── first_<STRUCT>.ply: FSL FIRST subcortical surfaces (same <STRUCT> set as fslfirst/).
│       ├── freesurfer_BEM_{brain,inner_skull,outer_skull,outer_skin}.ply: MNE watershed BEM
│       │   shells -- the nested 3-layer model OpenMEEG solves on. They MUST be strictly nested;
│       │   the QC report flags them when they are not.
│       ├── MNE_scalp.ply: MNE's dense scalp surface.
│       ├── freesurfer_{lh,rh}_{pial,white,middle}.ply: cortical surfaces; `middle` is the
│       │   midthickness surface the cortical dipoles are sampled on.
│       ├── freesurfer_{lh,rh}_middle_thickness.npy / _volume.npy: per-vertex thickness/volume
│       │   of the midthickness surface.
│       ├── freesurfer_{lh,rh}_middle_original_labels_<N>.npy: per-vertex Schaefer labels at
│       │   resolution N (100..1000), in the source atlas's own numbering.
│       ├── cereb_{gray,white}.ply: cerebellar pial/white surfaces (warped from the template).
│       ├── cereb_inner.ply: raw inner cerebellar surface (warped from the template).
│       ├── cereb_inner_processed.ply: the same surface made manifold -- THIS is the one the
│       │   cerebellar dipoles are sampled on.
│       ├── cereb_inner_processed_{original_labels,thickness}.npy: per-vertex labels/thickness
│       │   of cereb_inner_processed.ply.
│       ├── hippunfold_{L,R}_{hipp,dentate}_middle.ply: hippocampal/dentate midthickness surfaces.
│       └── hippunfold_{L,R}_{hipp,dentate}_middle_{original_labels,thickness}.npy: their
│           per-vertex labels/thickness.
│
├── atlas/: the Parrot multi-resolution atlases, built on the raw/ T1 grid. Each merges the
│   │       cortical Schaefer parcellation with the subcortical, cerebellar and hippocampal
│   │       segmentations into ONE label field with a single consistent numbering.
│   └── sub-<ID>/
│       ├── atlas<N>.nii.gz: atlas at cortical resolution N (100..1000 in steps of 100). N
│       │   counts the CORTICAL parcels only -- subcortex/cerebellum/hippocampus add their own
│       │   (>100) labels on top, identical across resolutions.
│       ├── atlas<N>_LUT.txt: LUT (label -> name + colour) for the volume above.
│       ├── atlas<N>_labels.txt: label list for the volume above.
│       ├── atlas_aggregated.nii.gz: coarse atlas -- 26 regions (24 subcortical + 1 per
│       │   cortical hemisphere).
│       ├── atlas_aggregated_{LUT,labels}.txt: LUT/labels for the aggregated volume.
│       ├── atlas_to_aggregated.json: mapping from any full-resolution label to its aggregated
│       │   region.
│       ├── freesurfer_surf/: {lh,rh}.<N>Parcels_labels.npy -- per-vertex labels of the
│       │   cortical midthickness surfaces, renumbered into the atlas numbering.
│       ├── cerebellum_surf/: cereb_labels.npy -- same, for cereb_inner_processed.ply.
│       └── hippunfold_surf/: {L,R}_{hipp,dent}_labels.npy -- same, for the hippocampal surfaces.
│
└── tissuelabels/: tissue label fields with electrical and acoustic properties attached. Plain
    │              3D (SimNIBS's degenerate trailing axis is squeezed here). The electrical
    │              side feeds the FEM meshes/solves; the acoustic side serves the AEGEUS
    │              ultrasound branch and is not used by the EEG forward model.
    └── sub-<ID>/
        ├── electrical/
        │   ├── ITIS_conductivities.txt: conductivity per tissue, from the ITIS database
        │   │   (reference table, not tied to one volume).
        │   ├── simnibs.nii.gz: label field from SimNIBS charm.
        │   ├── simnibs_{LUT,labels,conductivities}.txt: LUT / label list / SimNIBS's own
        │   │   conductivities for the volume above.
        │   ├── simnibs_itis.nii.gz: the SAME segmentation relabelled with ITIS tissue names.
        │   │   This is what the CGAL stream meshes when no sim4life volume exists.
        │   ├── simnibs_itis_{LUT,labels,conductivities}.txt: LUT / labels / ITIS conductivities
        │   │   for the volume above. NOTE the ITIS and SimNIBS tables disagree by 3-4x on
        │   │   several tissues, so the two CGAL/SimNIBS FEM leadfields are not directly comparable.
        │   ├── *_mesher_parameters.txt: per-volume CGAL mesher settings (sizing fields), copied
        │   │   in by the pipeline and consumed by the tetmesh stage.
        │   ├── sim4life.nii.gz: label field from sim4life -- OPTIONAL, produced manually
        │   │   outside the pipeline. When present it is PREFERRED over simnibs_itis for meshing.
        │   └── sim4life_{LUT,labels,conductivities}.txt: its LUT / labels / conductivities.
        ├── acoustic/: same file set (simnibs.nii.gz, sim4life.nii.gz when present, + LUT and
        │   │          labels), but with acoustic instead of electrical properties:
        │   ├── ITIS_{speed_of_sound,density,attenuation_constant,nonlinearity_parameter}.txt:
        │   │   reference tables from ITIS (nan where a value is not available).
        │   └── <volume>_{speed_of_sound,density,attenuation_constant,nonlinearity_parameter}.txt:
        │       the per-label values for that volume.
        └── sim4life_raw/: the unprocessed sim4life export, when one was supplied.


DIFFUSION (OPTIONAL -- only when the subject has DWI)
-----------------------------------------------------
├── qsiprep/: QSIPrep DWI preprocessing (BIDS-derivatives). Motion/eddy/SDC-corrected and
│   │         resampled into AC-PC-aligned subject space (space-ACPC), gradients rotated to match.
│   │         NOTE: AC-PC is NOT the mesh/T1 space -- see dwitensor/ for the bridge.
│   └── sub-<ID>/
│       ├── dwi/sub-<ID>_space-ACPC_desc-preproc_dwi.nii.gz (+ .bval/.bvec): preprocessed DWI
│       │   and its rotated gradient table.
│       ├── dwi/sub-<ID>_space-ACPC_desc-brain_mask.nii.gz: DWI brain mask.
│       └── anat/sub-<ID>_from-ACPC_to-anat_mode-image_xfm.mat: rigid ACPC<->T1 transform.
│           QSIPrep's "anat" is bit-identical to raw/T1, so the dwi2t1 stage REUSES this
│           transform rather than re-registering.
│
├── qsirecon/: QSIRecon tractography (MRtrix3; adaptive SS3T/MSMT spec, ACT-hsvs from FastSurfer).
│   └── sub-<ID>/
│       ├── dwi/sub-<ID>_space-ACPC_model-ifod2_streamlines.tck.gz: whole-brain tractogram
│       │   (10M streamlines) in ACPC space. NOTE: MRtrix cannot read .tck.gz -- decompress first.
│       ├── dwi/sub-<ID>_space-T1_model-ifod2_streamlines.tck.gz: the same tractogram carried
│       │   into T1/mesh space by the dwi2t1 stage. THIS is what the connectome is built from.
│       ├── dwi/sub-<ID>_space-ACPC_model-sift2_streamlineweights.csv (+ _mu.txt): SIFT2
│       │   per-streamline weights and the mu scaling factor.
│       ├── dwi/sub-<ID>_space-ACPC_model-ss3t_param-fod_label-{WM,GM,CSF}_dwimap.mif.gz:
│       │   the fibre orientation distributions the tracking ran on.
│       └── figures/: QSIRecon's own report figures.
│
├── dwitensor/: diffusion tensor for the WM anisotropic-conductivity model (MRtrix dwi2tensor +
│   │           tensor2metric). ALSO holds the DWI->T1 registration products -- the dwi2t1 stage
│   │           has no folder of its own.
│   └── sub-<ID>/
│       ├── sub-<ID>_space-ACPC_model-dti_tensor.nii.gz: 6-volume tensor fit in native ACPC space.
│       ├── sub-<ID>_space-T1_model-dti_tensor.nii.gz: tensor RE-FIT in T1/mesh space (ANTs
│       │   resample of the DWI + world-frame gradient rotation, then dwi2tensor again -- not a
│       │   tensor rotation).
│       ├── sub-<ID>_space-{ACPC,T1}_model-dti_param-eigvecs.nii.gz: eigenframe v1|v2|v3
│       │   (the orthotropic axes).
│       ├── sub-<ID>_space-{ACPC,T1}_model-dti_param-eigvals.nii.gz: eigenvalues (L1>=L2>=L3).
│       ├── sub-<ID>_space-{ACPC,T1}_model-dti_param-fa.nii.gz: fractional anisotropy.
│       ├── sub-<ID>_space-T1_desc-brain_mask.nii.gz: DWI brain mask in T1 space.
│       └── sub-<ID>_from-ACPC_to-T1_ras.txt: RAS 4x4 used to carry the DWI products into
│           T1/mesh space (converted from QSIPrep's transform; no re-registration).
│
└── connectivity/: subject structural connectome (tck2connectome), built in T1/mesh space.
    │              ABSENT entirely when DWI is missing or too sparse -- no template is copied
    │              in; substitute a group connectome at simulation time if you need one.
    └── sub-<ID>/
        ├── atlas<N>_connectivity.nii.gz: the connectivity node parcellation at resolution N --
        │   the Parrot atlas collapsed to the nodes that actually survive as connectome nodes,
        │   renumbered 1..n_nodes contiguously.
        ├── labels_<N>.txt: node names, in node order, for the parcellation above.
        ├── reduced_to_full_<N>.npy: full_id = reduced_to_full[node_id] -- maps a connectome
        │   node back to its label in atlas<N>.nii.gz.
        ├── full_to_reduced_<N>.npy: node_id = full_to_reduced[full_id], -1 for labels that were
        │   dropped. The inverse of the above; use it to project atlas-space data onto nodes.
        ├── weights_<N>.txt: SIFT2-weighted streamline-count connectome (TVB coupling weights).
        ├── weights_invnodevol_<N>.txt: the same, normalised by node volume (graph metrics).
        ├── distances_<N>.txt: mean streamline-length connectome (TVB conduction delays), in mm.
        └── assignments_<N>.txt: per-streamline node assignments -- lets you re-derive edges
            without re-running tractography.


FORWARD MODEL
-------------
├── scalplandmarks/: subject landmarks on surfaces/charm_scalp.ply, written by the fiducials
│   │                stage (it has no folder of its own).
│   └── sub-<ID>/
│       ├── fiducials.json: NAS, IN, LPA, RPA positions in world space, written by
│       │   make_fiducials.py: MNI coordinates warped in with SimNIBS's mni2subject_coords
│       │   and snapped to charm_scalp.ply. LPA/RPA come from the median of 20 hand-picked
│       │   LEMON subjects, NOT from SimNIBS's own template -- those are ~7.6 mm posterior
│       │   (100% of 40 picks), which lands them on the pinna, where the coronal cut used to
│       │   bisect for Cz wraps ear cartilage and tilts the whole montage. NAS/IN keep the
│       │   SimNIBS values (no significant bias; the inion has ~9 mm of scatter).
│       │   REQUIRED by electrodes -- there is no longer a fallback deriving it from the
│       │   SimNIBS CSV. Drop in a hand-picked file here to override it; make_fiducials
│       │   refuses to overwrite a file it did not write unless --force, so manual picks
│       │   survive a rerun. The montage is built from these four points and inherits any
│       │   error in them.
│       ├── fiducials_provenance.json: what wrote fiducials.json, the MNI coordinates used,
│       │   and the per-point snap distance to the scalp. Its ABSENCE is what marks
│       │   fiducials.json as hand-picked or legacy, and so protects it from being replaced.
│       └── outlines.npy: OPTIONAL INPUT, not an output. Right-ear / left-ear / eye outlines
│           used to exclude electrodes that land on them. There is NO fallback: when this file
│           is absent, place_electrodes.py performs no exclusion at all and the "selected"
│           montage equals the full one. Supply it by hand if you need ear/eye clearance.
│
├── electrodes/: 10-5 montage sampled on surfaces/charm_scalp.ply.
│   └── sub-<ID>/
│       ├── landmarks_10-5-full.csv: all 10-5 electrode positions, in world space.
│       ├── selected_landmarks_10-5-full.json: the electrodes kept after ear/eye exclusion --
│       │   identical to the full set unless scalplandmarks/outlines.npy was supplied.
│       │   THIS subset, in this order, is the row order of every leadfield.
│       └── placement_qc.json: ear-approach tortuosity (arc/chord over the last 30 mm of the
│           coronal cut before each preauricular point). ~1.00 means the cut ran over smooth
│           scalp; >1.1 means it wrapped the pinna, which biases Cz and tilts the montage.
│           Thresholded by the electrodes QC stage (warn 1.08, fail 1.25).
│
├── dipoles/: source dipoles, Poisson-disk sampled on the surfaces and in the subcortical
│   │         volumes. Pre-sampled at all three spacings; each solver then uses its own.
│   └── sub-<ID>/
│       ├── legend.txt: the per-file dipole contract, written by the pipeline. Read it -- it is
│       │   authoritative for this folder.
│       └── spacing<S>mm/: one folder per spacing S (2.0 / 3.0 / 4.0 mm; set by
│           │              --spacing-duneuro-cgal / -duneuro-simnibs / -openmeeg).
│           │  The files at THIS level are the aggregated set: all surface and volumetric
│           │  dipoles concatenated. This is the source order every leadfield column follows.
│           ├── dipole_positions.npy: (N,3) dipole positions in world space.
│           ├── dipole_directions.npy: (N,3) preferential orientation per dipole.
│           ├── dipole_volume.npy: (N,) grey-matter volume attributed to each dipole (mm^3).
│           ├── dipole_neural_density.npy: (N,) BigBrain-derived neuronal density per dipole.
│           │   Scales the processed leadfields -- a broken BigBrain warp shows up here as zeros.
│           ├── orient_type.npy: (N,) how each orientation was chosen -- one of 'U' unassigned,
│           │   'N' normal to a surface, 'G' gradient of a smoothed structure, 'P' principal
│           │   axis of the structure, 'R' random on the unit sphere.
│           ├── <N>Parcels_dipole_labels.npy / aggregated_dipole_labels.npy: (N,) atlas label
│           │   per dipole, one array per atlas resolution plus the aggregated atlas.
│           ├── surfaces/<surface_name>/: the per-surface subsets (freesurfer_{lh,rh}_middle,
│           │   cereb_inner_processed, hippunfold_{L,R}_{hipp,dentate}_middle).
│           │   Same contract, except the orientation file is dipole_normals.npy, plus:
│           │     dipole_traceback.npy: (N,) boolean index into the aggregated arrays, so
│           │       aggregated[traceback] == this subset;
│           │     distance_matrix.npy: geodesic distances between this subset's dipoles.
│           └── volumetric/: the subcortical/volumetric subset. Same contract, except the
│               orientation file is dipole_preferential_direction.npy; also has
│               dipole_traceback.npy and distance_matrix.npy (Euclidean, within-structure).
│
├── tetmesh/: CGAL tetrahedral volume mesh of the head (the C++ mesher). Built from the
│   │         preferred electrical label field -- sim4life when present, else simnibs_itis.
│   └── sub-<ID>/
│       ├── label_field.inr: the label volume converted to INR, the mesher's input.
│       ├── tetrahedral_mesh.mesh: the mesh itself (MEDIT format) -- DUNEuro's FEM input.
│       ├── tetrahedral_mesh.vtu: the same mesh for visualization (ParaView/PyVista).
│       ├── labels.txt / LUT.txt / conductivities.txt: copies of the meshed volume's label
│       │   list, LUT and conductivities, frozen next to the mesh so a leadfield can always be
│       │   traced back to the exact table it was solved with.
│       └── mesher_parameters.txt: the CGAL sizing/criteria used for this mesh.
│
├── anisotropy/: white-matter anisotropic conductivity tensors for the CGAL FEM leadfield,
│   │            from the subject DTI (+ the cerebellar template DTI where it applies).
│   │            Present only when a subject DTI exists.
│   └── sub-<ID>/
│       ├── conductivity_tensors.npy: (M,3,3) per-WM-tetrahedron conductivity tensors
│       │   (shape-preserving orthotropic; geometric mean fixed to the isotropic WM sigma).
│       └── wm_element_indices.npy: (M,) indices of those tetrahedra in tetrahedral_mesh.mesh,
│           mapping each tensor to its element.
│
├── forwardsolvers/: RAW solver output -- the leadfield exactly as DUNEuro/OpenMEEG returned it,
│   │                per unit dipole moment, no reference applied. Kept for debugging and for
│   │                re-deriving the processed version with different weighting. For analysis,
│   │                use leadfields/ instead.
│   └── sub-<ID>/
│       ├── raw_openmeeg-<S>mm-leadfield.npy
│       ├── raw_duneurosimnibs-<S>mm-leadfield.npy
│       ├── raw_duneuroCGAL-<S>mm-leadfield.npy
│       ├── raw_duneuroCGAL_anisotropic-<S>mm-leadfield.npy (when anisotropy ran)
│       └── raw_duneuro_artifact-{eyes,muscle}-CGAL-leadfield.npy
│
└── leadfields/: PROCESSED leadfields -- the pipeline's endpoint. Shape (n_electrodes,
    │            3*n_dipoles): rows are the selected 10-5 montage in the order of
    │            electrodes/selected_landmarks_10-5-full.json, columns are free-orientation
    │            (x,y,z) triplets in dipole order. Processing = raw, scaled per dipole by
    │            grey-matter volume x BigBrain neuronal density x an orientation-type strength
    │            factor, then average-referenced.
    └── sub-<ID>/
        ├── processed_openmeeg-<S>mm-leadfield.npy: BEM, on the MNE watershed shells
        │   (--spacing-openmeeg, default 4 mm).
        ├── processed_duneurosimnibs-<S>mm-leadfield.npy: FEM on the SimNIBS charm mesh, with
        │   SimNIBS conductivities (--spacing-duneuro-simnibs, default 3 mm).
        ├── processed_duneuroCGAL-<S>mm-leadfield.npy: FEM on the CGAL mesh, with ITIS
        │   conductivities (--spacing-duneuro-cgal, default 2 mm).
        ├── processed_duneuroCGAL_anisotropic-<S>mm-leadfield.npy: the same CGAL solve with
        │   anisotropic WM tensors. Present only when the anisotropy stage ran.
        ├── processed_duneuro_artifact-eyes-CGAL-leadfield.npy: geometry-only eye artifact
        │   leadfield, (n_elec, 3*n_eye_sources). Same montage/reference, so it stacks directly
        │   onto a brain leadfield.
        ├── processed_duneuro_artifact-muscle-CGAL-leadfield.npy: the same for muscle sources,
        │   solved on the subject mesh (shares the eye solve's transfer matrix).
        └── processed_hartmut_muscle-leadfield.npy: FALLBACK muscle leadfield -- HArtMuT's canned
            NYhead leadfield interpolated onto the subject montage. Present INSTEAD of the solved
            one when too few muscle sources survived the warp (no neck FOV).


EEG ARTIFACT SOURCES
--------------------
└── artifacts/: extra-brain physiological noise sources (eyes + face/neck muscle). FEM/CGAL only.
    │           Present only when the artifacts stage ran -- it skips gracefully when the
    │           HArtMuT/MNI template assets could not be fetched. The artifact LEADFIELDS live
    │           in leadfields/, next to the brain ones, because they are stackable siblings.
    │           NOTE this stage nests sub-<ID>/ one level DEEPER than the others.
    ├── registration/sub-<ID>/: subject<->MNI (MNI152NLin2009cAsym) affine, used to bring
    │   │                       template artifact geometry into the subject.
    │   ├── mni_to_subject_affine.npy: (4,4) RAS-world affine, MNI -> subject T1/mesh frame.
    │   ├── subject_to_mni_affine.npy: (4,4) the inverse; maps the subject montage into template
    │   │   space for the fallback electrode interpolation.
    │   ├── ants_affine.mat: the raw ANTs (antspyx) transform.
    │   └── registration_qc.json: both scalp residuals (mm). The GATED one is
    │       template->subject (NYhead scalp mapped through the affine, distance to charm_scalp);
    │       ~2-3 mm is correct. subject->template sits at 14-15 mm even for a good affine and is
    │       recorded but not gated -- it barely separates a correct fit from a mirrored one.
    └── dipoles/sub-<ID>/: the artifact source dipoles -- a small fixed set, spacing-independent.
        ├── eyes/: dipoles sampled NATIVELY inside surfaces/charm_eyes_balls.ply. Same file
        │   contract as the brain volumetric dipoles (dipole_positions / _volume / _labels /
        │   dipole_preferential_direction / orient_type .npy). The preferential direction stores
        │   the per-eye corneo-retinal axis -- metadata for the future EOG generator, not used
        │   by the geometry-only leadfield.
        ├── muscle/: face/neck muscle dipoles -- HArtMuT NYhead template positions warped into
        │   the subject (affine + ray-cast layer-normalized projection preserving skull<->scalp
        │   depth fraction, cast against surfaces/charm_bone_compact.ply and charm_scalp.ply).
        │   Same file contract.
        ├── artifactsources.json: the machine-readable record of what survived, and the file the
        │   orchestrator reads to choose the muscle path (solve vs canned fallback).
        │     eyes: {n_dipoles, n_dropped_near_electrode}
        │     muscle: {n_kept, n_dropped, n_total, n_in_fov, n_below_fov, n_dropped_raycast,
        │              n_raycast_kept_in_fov, n_dropped_near_electrode, kept_fraction,
        │              raycast_fraction, has_neck_fov, scalp_z_min_mm, solve_muscle,
        │              neck_coverage, min_electrode_distance_mm, min_clearance_mm}
        │   Sources are dropped for two independent reasons: the ray-cast warp missed, and the
        │   source landed within --artifact-electrode-gap mm of an electrode (a point dipole's
        │   1/r^2 potential would otherwise swamp that channel).
        │   solve_muscle decides the path: true -> solve on the subject mesh, false -> interpolate
        │   the canned HArtMuT leadfield onto the montage. It requires that enough of the IN-FOV
        │   sources survived the warp AND that enough sources remain in absolute terms; it is a
        │   "is this scalp mesh usable" test, NOT a neck test. neck_coverage is a deprecated alias
        │   carrying the same value (its old name claimed to measure neck coverage but only ever
        │   counted ray hits, which is why sub-MNI09b read true on a head with no neck at all).
        │   has_neck_fov is the separate, honest label: false means the head model stops above the
        │   neck (scalp_z_min_mm), so the n_below_fov sources whose true home is below that floor
        │   are placed on the open bottom rim rather than at their real depth -- their positions
        │   are unreliable even though their leadfield columns are numerically fine. They are kept
        │   rather than dropped because they still carry ~25% of the muscle-artifact energy.
        └── solve_groups.json: which source groups share one DUNEuro transfer matrix. The
            expensive solve depends only on mesh/conductivities/electrodes, not on the dipoles,
            so eyes and muscle are solved together.


QUALITY CONTROL
---------------
└── qc/: final cross-stage QC (parrot_qc image). Validates the outputs of every stage and
    │    renders a human-review report. Always re-runs (not log-guarded) and never blocks the
    │    pipeline -- a QC failure is a WARNING only.
    ├── index.html: GROUP report -- subject x stage pass/warn/fail/skip matrix, linking to each
    │   subject report. Refreshed after the subject loop.
    └── sub-<ID>/
        ├── index.html: the per-subject report -- status table + embedded figures. OPEN THIS.
        ├── qc_report.json: machine-readable record, {stage: {status, checks[], figures[]}}.
        │   status is pass | warn | fail | skip; skip = the stage was not produced (optional
        │   stages such as the DWI ones degrade gracefully, they never fail).
        └── figures/: the PNGs index.html references -- 2D label/FA overlays (nilearn) and 3D
            snapshots (pyvista offscreen: BEM nesting, subcortical surfaces, dipole cloud,
            mesh cross-section, artifact sources, sample topographies).


NOT PRODUCED BY THIS PIPELINE

run via bin/stage.sh) or picked by hand, and run_reconstruction.sh neither writes nor reads them:

    manualscalplandmarks/sub-<ID>/ hand-picked fiducials, kept aside for comparison against
